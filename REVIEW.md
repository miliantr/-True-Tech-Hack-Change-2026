# Проверка и сдача EnergyTool

## Сценарии проверки

| Сценарий | Действия | Ожидаемый результат |
|---|---|---|
| Консультация и заявка | Опишите задачу учёта по складам, добавьте уточнение, заполните тестовую форму. | Заявка содержит исходный запрос, уточнение и следующий шаг. Повторная отправка сохраняет тот же ID. |
| Отказ оставить контакты | Откройте форму и закройте её. Продолжите разговор и начните новый диалог. | Ответы продолжаются. В архиве виден предыдущий диалог без заявки. |
| Граница консультации | Спросите, можно ли гарантировать окупаемость станции или получить пароль прибора. | С подключённой моделью помощник объясняет ограничение и предлагает специалиста. |
| Проверка контекста | Уточните параметр объекта, смените тему и вернитесь к исходной теме. Затем начните новый диалог. | В текущем разговоре сохранён контекст. Новый разговор начинается без него. |
| Отладка | Войдите в режим проверяющего и откройте сохранённый диалог. | Видны время и фрагменты, отобранные поиском. Ключ проверяющего требуется для доступа к истории. |

Без прокси браузер показывает выбранный фрагмент и сохраняет историю. Проверки формулировок и поведения консультанта выполняются в режиме генерации.

## Проверка поиска и ответов

- `python evaluate.py` проверяет наличие опорных фрагментов на 18 примерах организаторов.
- `python evaluate.py --suite development --compare` сравнивает 3, 6 и 10 основных фрагментов до добавления продуктовых оговорок. Сравнивайте полноту источников, время поиска и объём контекста.
- `python evaluate.py --suite holdout` проверяет 10 отложенных вопросов после выбора конфигурации. Ответы на вопросы без подтверждающего источника требуют ручной оценки.
- `python evaluate.py --suite development --compare --proxy` сравнивает лексический, гибридный и гибридный с реранжированием поиск через разрешённый прокси. Ошибки API и переходы на резервный поиск отражаются в отчёте.
- `python evaluate.py --suite holdout --proxy --generate` сохраняет ответы для проверки по `expect` и `avoid`. Отмечайте наличие подтверждения, корректность чисел, уместность уточнения и отсутствие обещаний. Не отправляйте ответы внешнему судье без разрешения на обработку материалов.

Автоматическая метрика поиска проверяет наличие заданных опорных фраз. Финальная оценка качества зависит от смысла ответа и контекста разговора. Тесты с локальным имитатором проверяют передачу истории, форматы API, идемпотентность заявки и полноту CSV.

| Демо и разработка | Найдены все опорные фразы в 18 из 18 демо-вопросов и 22 из 22 размеченных вопросов разработки. Четыре сценария разработки без источника требуют проверки ответа модели. |
| Отложенная выборка | В первоначальной версии найдены все опорные фразы в 7 из 8 размеченных вопросов. После исправления поиска по формулировкам об окупаемости результат повторной проверки — 8 из 8. Два вопроса без источников требуют ручной проверки ответа. |
| Чистый Docker запуск | Образ собран из распакованного финального ZIP с отдельной базой организаторов. Проверены заявка, просмотр истории, сброс и сохранение истории после перезапуска контейнера. |

Проверка через прокси организаторов, оценка содержания ответов и результат на платформе зависят от доступа к среде команды. В отчётах по лексическому поиску время генерации отсутствует.

Первая версия получила `0.54831` на публичном лидерборде. Её архив сохранён локально как `dist/HARAKIBON_2026-11-10_04-27-03-886.zip`. У автоматического Score шкала 0–1. Экспертная оценка использует отдельную шкалу 0–5. Для следующего запуска сравните новый Score с исходным на той же выборке и сохраните Match Rate, Win Rate и счётчики ошибок из лога, если они доступны.

Версия `dist/HARAKIBON_2026-11-10_11-37-36-474.zip` с изменённым промптом и поиском получила `0.48262`. Следующий контролируемый эксперимент — `dist/HARAKIBON_2026-11-10_11-57-51-963.zip`. Он сохраняет промпт, генерацию, обработку диалога и размер основного контекста версии `0.54831`. Реранкер выбирает из 20 лексических кандидатов. На вызов отводится до четырёх секунд с резервом 12 секунд на генерацию. При недоступности реранкера используется исходный порядок. Имитатор прокси подтвердил 18 валидных строк CSV и совпадение всех запросов генерации с исходной версией при ответе HTTP 404. Результат на платформе пока неизвестен.

Готовый архив для финальной сдачи — `dist/HARAKIBON_2026-11-10_11-37-36-627.zip`. В именах готовых архивов используется московское время.

## Порядок отправки

1. После тестов собрать `dist/submission.zip` командой `python package_submission.py`.
2. В рабочем пространстве команды отправить архив на автоматическую оценку. Сохранить ID, режим поиска, результат и время. Для допуска нужен положительный балл.
3. Если доступны сравнимые результаты, выбирать вариант по качеству ответов, времени и стабильности. Менять за отправку один параметр. Учитывать лимит пяти отправок в сутки.
4. Пересобрать финальный архив командой `python package_final.py`. Проверить его с отдельно выданным организаторами `knowledge-base.zip`.
5. Отправить `dist/EnergyTool-final.zip` в финальную форму. Внутри находятся код, Docker Compose, README и PDF презентация.
